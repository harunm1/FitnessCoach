# Import formats: Hevy and Strong workout CSV

What the import (#131) reads, with the source of every claim. Checked 22 November 2026. **Hevy and Strong publish no column reference.** Their help pages say that a CSV export exists and where to tap, and nothing more, so the column lists below come from third-party importers that read real files. Treat them as unverified against a file exported today; the importer therefore checks the header and says what is missing instead of guessing.

## Hevy workout export (implemented)

**Official** ([Exporting Your Data from Hevy](https://help.hevyapp.com/hc/en-us/articles/43708290987415-Exporting-Your-Data-from-Hevy), checked 22 Nov): Profile > Settings > Export & Import Data > Export Data > Export Workouts. The file opens in a spreadsheet as a CSV. Measurements are a separate export. The page names no column. [How to Import Strong App CSV Files and Export Your Data in Hevy](https://help.hevyapp.com/hc/en-us/articles/38001424401943-How-to-Import-Strong-App-CSV-Files-and-Export-Your-Data-in-Hevy) (checked 22 Nov) says Hevy itself only imports Strong CSVs, so a Hevy file cannot be re-imported into Hevy.

**Third party, one row per set.** Header seen by importers ([Gript, Hevy export guide](https://griptapp.com/help/export-workouts-from-hevy); the header string in a developer thread, [r/iosdev](https://www.reddit.com/r/iosdev/comments/1xmw4wz/im_collecting_export_structures_of_workout_apps/), both checked 22 Nov):

| Column                                                    | Meaning                                                                                                                                                                | Used by us                                      |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `title`                                                   | Workout name, repeated on each set row                                                                                                                                 | Workout title shown in Progress                 |
| `start_time`                                              | Session start, repeated on each set row                                                                                                                                | `startedAt`, and with the title the dedupe key  |
| `end_time`                                                | Session end                                                                                                                                                            | `finishedAt` (falls back to the start)          |
| `description`                                             | Workout note                                                                                                                                                           | Ignored                                         |
| `exercise_title`                                          | Exercise name in Hevy's library                                                                                                                                        | Matched to our library                          |
| `superset_id`                                             | Superset group                                                                                                                                                         | Ignored                                         |
| `exercise_notes`                                          | Note on the exercise                                                                                                                                                   | Ignored                                         |
| `set_index`                                               | Position of the set within the exercise, zero-based in a Liftosaur test file                                                                                           | Order only; we number sets 1, 2, 3 per exercise |
| `set_type`                                                | `normal`, `warmup`, `failure`, drop set and cool down (Gript writes them with a space; the exact strings are unverified)                                               | `warmup` rows are skipped; the rest are kept    |
| `weight_kg` or `weight_lbs`                               | Load; the column present depends on the user's Hevy unit setting. The openweight converter reports that Hevy's CSV can carry both columns and reads whichever has data | Converted to kg (1 lb = 0.45359237 kg)          |
| `reps`                                                    | Repetitions                                                                                                                                                            | `reps`                                          |
| `distance_km` (named in a developer thread, not by Gript) | Cardio distance                                                                                                                                                        | Ignored (runs are not imported)                 |
| `duration_seconds`                                        | Time for timed sets                                                                                                                                                    | Ignored                                         |
| `rpe`                                                     | Effort, when logged                                                                                                                                                    | `rpe` when it is a whole number from 1 to 10    |

**Dates.** The format is not documented and varies with the phone's locale. Importers read `%d %b %Y, %H:%M`, for example `20 Jun 2024, 18:30` ([dailybuild issue 153](https://github.com/tsu-nera/dailybuild/issues/153), which also reports a Japanese-locale export that breaks that format), and Liftosaur has a test for a US 12-hour form ([importFromHevy.test.ts](https://github.com/astashov/liftosaur/blob/38bdce0446ce2971b9d852930ba81af2cdd004b4/test/importFromHevy.test.ts)). Gript warns that a spreadsheet can rewrite the dates, and that all-numeric dates can be day-first or month-first. Our rule: accept `D MMM YYYY, HH:mm`, `MMM D, YYYY, h:mm AM/PM` and `YYYY-MM-DD HH:mm[:ss]` (English month names, no ambiguity); refuse any other date with the row number and an instruction to upload the untouched export. We never guess between day-first and month-first. All times are read as the user's local time in `America/Toronto`, the app's `DEFAULT_TIME_ZONE`, because the file carries no zone.

## Strong workout export (specified, not implemented)

**Official** ([Can I export my workout data?](https://help.strongapp.io/article/235-export-workout-data), last updated 27 April 2021, checked 22 Nov): Settings > Export Strong Data on iOS, Settings > Export Data on Android; the CSV cannot be imported back into Strong. No column list.

**Third party** ([Gript, Strong export guide](https://griptapp.com/help/export-workouts-from-strong), checked 22 Nov): `Date`, `Workout Name`, `Duration`, `Exercise Name`, `Set Order`, `Weight`, `Reps`, `Seconds`, `Notes` and `Workout Notes` (with notes), `RPE`. `Weight` holds a bare number in the unit of the user's Strong setting, so a Strong import has to ask the user for the unit. Strong is not in this change: the unit question and a real sample file are needed first.

## What the importer does with them

- A file over 2 MB is refused before it is read; one with more than 20,000 rows is refused right after it is read as CSV.
- The header must contain `title`, `start_time`, `exercise_title`, `reps` and one of `weight_kg` or `weight_lbs`. A file missing one is refused and the missing names are listed.
- One workout per `title` plus `start_time`. Its dedupe key is the start time as an ISO string plus the title, and a unique index on the user and that key means uploading the same file twice adds nothing.
- Exercise names are matched to our library exactly (case and spacing ignored), then by alias (Hevy writes the equipment in brackets: `Bench Press (Barbell)`), and what is left is listed for the user to map to a library exercise or skip. Skipped names drop their sets; a workout left with no sets is not saved.
- Saved workouts carry `source = "hevy-import"` and the original timestamps. They are not logged live in FitnessCoach: Progress shows them with an "Imported" label and counts them separately, and, since 25 Nov (D34), they count toward the weekly streaks, labelled as imported history, and feed the training profile (experience level, working weights, usual training time).
- A time that does not exist in Toronto (spring forward, for example 02:30 on 10 March 2024) is read one hour early, and an ambiguous one (autumn, 01:30 on 3 November 2024) as the first of the two.
- A workout is skipped as already imported when its start time and title match an earlier upload, even if the earlier upload skipped some exercises. To add sets the first upload skipped, there is no re-import yet.
- The bare-name match takes the equipment off, so `Curl (Cable)` can pair with a plain `Curl` when that is the only one with that name.
- After Import, the page shows a result panel and moves focus to it (25 Nov 2026, live feedback: the long preview collapsed and the page looked as if it had reset). It reports the workouts and sets saved, the workouts already imported, and what was left out with the reason: timed sets (no reps), warm-up sets, and sets of exercises with no library match, with up to ten of those names.
- Name matching, 25 Nov 2026 (live feedback after a real export: 51 of 80 names unmatched against the 876-exercise library). Both sides are reduced to a spelling-tolerant key (`src/lib/import/matchKey.ts`: case, hyphens, spacing, plurals, closed or spaced words such as `Push Up` and `Pushups`, the typos `Dumbell` and `Palloff`). For `Name (Equipment)` the tried forms are the whole title, the equipment first (`Weighted Pull Ups`), the bare name, and then the alias table (`src/lib/import/aliases.ts`). Every alias target is an exact library name, checked against free-exercise-db `dist/exercises.json` fetched 25 Nov 2026; a target the library lacks leaves the title unmatched. **Option it beat:** automatic fuzzy matching (edit distance or token overlap) for everything left. It would match more names, but a wrong silent match writes sets to the wrong exercise in the user's history, while an unmatched name only costs the user one choice in the preview. So a name that is not a spelling variant or a listed alias stays unmatched, and the import summary lists those names.
