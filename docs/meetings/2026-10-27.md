## What we discussed

- **Proposal split.** Sections 1, 2 and 4 each have an owner; section 3 (plan and responsibilities) is written together, starting from `docs/PLAN.md`. A proposal from another course with the same instructor is used as a structural reference. The 2,000-word limit is split by the marking weights: about 350 words for section 1, 900 for section 2, 300 each for sections 3 and 4, with some buffer.
- **Schema walkthrough.** Everyone is a user, and the access tier (free, trial, pro, admin) is a field on the user. Admin is for managing app content such as the exercise library. Coach messages are stored with a role: `USER` for what the person types, `ASSISTANT` for the coach's reply. No other questions on the schema.
- **Backend.** Next.js for both front end and back end, with no separate API server (decision D1). External APIs: the LLM for the coach, Stripe in test mode, and cloud storage for files.
- **LLM provider (#7).** Gemini and Groq both have supporters; the coach is built so the provider is one setting, so both will be tried on the same test profiles before choosing.
- **Scope (#12).** Running is in scope from the start alongside gym training. Running plans are built by the coach's backend; the session and progress screens add a distance-and-time view.
- **Nearby gyms.** A map of nearby gyms was suggested as an extra. No API publishes gym membership prices and scraping gym sites is unreliable, so the idea is to look at a map of nearby gyms from OpenStreetMap first.
- **Cloud storage.** The course handout requires cloud storage for basic file handling: upload and download tied to the backend and database, for every project. Progress photos stay as the file feature, stored and viewed only, with no analysis; resizing and removing location data before saving are optional. A profile picture is a fallback if photos are dropped. A scheduled database backup to the bucket is a possible extra but does not on its own meet the requirement, since it is not app functionality. The storage provider is still open.
- **Stripe.** The risk is time, mostly the webhook setup. It stays off the core demo path (sign-in, quiz, plan, logged workout, coach) and is shown in the final product if it works by the 26 November feature freeze.
- **Workflow.** Branch protection on `main` is on. Each person works on their own branches and opens a pull request with teammates as reviewers. Commit history counts toward individual contribution, so everyone commits their own work.
