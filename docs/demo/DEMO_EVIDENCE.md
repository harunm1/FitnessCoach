## Live database proof: `scripts/demo-db-peek.ts`

Reads the latest `SetLog` rows, the latest `Workout` rows and the latest `ProgressPhoto` rows for one account, with times in Toronto time to the second and the R2 key of each photo. The columns are `SetLog.loggedAt`, `Workout.startedAt` and `ProgressPhoto.takenAt` (there is no `createdAt` on these tables). The set time is the first save: editing an existing set keeps it, so on stage log the next set number, not an edit.

Read-only by construction: the whole query runs in one transaction whose first statement is `SET TRANSACTION READ ONLY`, and only `findFirst`, `findMany` and `count` are used. An unknown email, a usage error or a failed connection prints one line (the error name and code only, never the host, user or connection string) and exits 1. Checked on 25 Nov against a scratch PostgreSQL 16 container with the real migrations applied: the same transaction pattern refuses an `UPDATE` (`Code: 25006 ... cannot execute UPDATE in a read-only transaction`), and the same `UPDATE` without the first statement succeeds. Tests: `scripts/demo-peek/peek.test.ts` (18 unit tests, written first and seen failing) and `tests/integration/demo-peek.test.ts` (2 tests on a real PostgreSQL: only BEGIN, SET TRANSACTION READ ONLY, SELECT and COMMIT are sent, no row changes, and a write in the same transaction is refused; the test fails when the READ ONLY line is removed). A blind review pass and a delta check were run on pull request #178. Not yet run against the Neon production database (see the gaps).

Run it (Windows PowerShell 5.1), once before the demo and again after logging a set or uploading a photo:

```powershell
cd "C:\Projects\Fall2026_Courses\ECE1724_Advanced_Web_Development\Project\FitnessCoach"
$env:DATABASE_URL = "<the connection string of the database the app uses>"
npx tsx --env-file=.env scripts/demo-db-peek.ts <demo account email>
```

`--env-file=.env` never overrides a variable already set, so setting `DATABASE_URL` first points the script at the deployed database and leaving it out uses the local `.env`. The script never prints the connection string. Do not show the line that sets `DATABASE_URL`: set it before the audience sees the terminal.
