# 90-second demo script

For the live part of the 6-minute talk (about 90 seconds; the 24 Nov minutes aim at about 75 for the clicks alone, so the cut order is at the end). Order, as the rubric rewards signposting: architecture, live workflow, database proof, cloud storage proof, advanced features, plan to 6 December. The lines are prompts: say them in your own words (course rule). The evidence behind every claim is in `docs/demo/DEMO_EVIDENCE.md`; the older, longer click path is `docs/DEMO_SCRIPT.md`. The spoken lines total about 200 words, roughly 80 seconds at 150 words a minute, so the clicks must overlap the speech; the script has not been timed with a stopwatch on the live site yet (no demo account, see `docs/demo/DEMO_EVIDENCE.md`). Who speaks which part is Mohammad's call in #162; Farnaz drives the laptop and does not speak (24 Nov decision 4).

## Before you start (10 minutes ahead)

- Browser at 1280 x 720, zoom 100%, signed out, on `/sign-in`. A second laptop is already signed in as the fallback.
- A terminal window, already in the repository folder on main, with the database connection set before the audience sees it. Run the peek once as a baseline (command in `docs/demo/DEMO_EVIDENCE.md`, "Live database proof"), then clear the line so the only visible command is the peek itself.
- The prepared photo is in the browser's file chooser folder. Backup recording of the photo and coach steps is open in another window (it supplements the live demo, never replaces it).

## Rules on stage

- One action per click; say what happened after it. Never press **Log set** twice.
- Nothing has answered after 3 seconds: say what it is doing ("the request is on its way to the server"). After 6 seconds: use the fallback in the table.
- Never open `/account`, billing or an admin view. Never show the line that sets the database connection.
- Stop at 90 seconds on the clock whatever step it is on. Cut in this order if time is short: the second peek (step 4), then the sign-in typing (use the second laptop), then the coach line (play the recording).

## Download step (added 25 Nov, downloads task; optional insert after step 4)

Cloud storage also covers downloading (D33). Use it only when there is time; the 90-second table above is unchanged.

1. After the upload in step 4, open the photo (click the thumbnail), press **Download**. Say: "The file comes back through a route that first checks the photo is mine, then a 60-second signed link; the browser saves it as `progress-photo-<date>.webp`."
2. For the data side, go straight to `/account/data` by its address (the rules above keep `/account` itself closed). Press **Export workout history (CSV)**, then **Download** on the new row. Say: "The server built this file, stored it in the same private bucket, and recorded it in the `DataExport` table; another user's id answers 404."
3. If the download does not start within 3 seconds: say the link is a 60-second signed link, press the button again; fallback is the file listed in the table (the row proves it is stored).
4. Optional: on the same page press **Make the monthly report (PDF)** and **Download**. Say: "A PDF made on the server with the month's sessions, volume per muscle group and personal bests, stored in the same bucket."
